## Организация кода

task-service.js — 10 чистых функций, без DOM и storage.

form-validation.js — validateTaskDraft, чистая функция.

task-storage.js — 4 функции, принимающие storage аргументом (можно подменить MemoryStorage в тестах).

task-view.js — создаёт DOM, не меняет данные.

main.js — состояние (currentTasks, currentFilter, editingId), обработчики и координация.

Почему storage аргумент: тестируемость и явная зависимость. Почему JSON проверяется: успешный JSON.parse — только синтаксис, схема может быть любой.

## Отладка и клавиатура

Точка останова в handleFormSubmit. При добавлении 20 / Изучить localStorage / high:

formData.get("id") → "20" (string), get("title") → "Изучить localStorage";

validateTaskDraft → { ok: true, value: { id: 20, title: "Изучить localStorage", priority: "high" } };

addTask(...) → { ok: true, tasks: [...] } из 5 записей;

saveTasks пишет {"version":1,"tasks":[...]}.

При повторном id=4: validateTaskDraft → { ok: false, errors: { id: "..." } }, storage не изменён.

Tab переводит фокус на кнопки карточек, Enter/Space активируют. После toggle фокус остаётся на кнопке той же задачи; после удаления — на активном фильтре. В режиме edit фокус переходит на поле title, в режиме create — на id.

## Вывод

Форма и хранение добавлены поверх логики ПР2–ПР3 без дублирования правил модели: task-service.js не знает о DOM и storage, validateTaskDraft — чистая функция, task-storage.js принимает storage аргументом. Нативная проверка дополнена прикладной, а данные из JSON проверяются по полной схеме до использования. Возможные ошибки чтения/записи перехватываются с fallback на исходный набор.
