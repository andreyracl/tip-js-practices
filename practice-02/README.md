## 4. Модель данных и функции

Модель задачи: { id, title, completed, priority }.

id — положительное безопасное целое (Number.isSafeInteger(id) && id > 0).

title — строка, trim(), длина 1..100.

completed — boolean, при создании всегда false.

priority — "low" | "medium" | "high", по умолчанию "medium".

Файлы:

src/data.js — исходные наборы, номера вариантов, без логики.

src/task-service.js — 9 прикладных функций, без console.log.

src/main.js — сценарии, вывод, обработка отказов.

checks.js — проверочный сценарий.

Результаты операций:

createTask — { ok: true, task } или { ok: false, error }.

Функции чтения — объект/массив/undefined, без обёртки.

addTask, setTaskCompleted, renameTask, removeTask — { ok: true, tasks } или { ok: false, error }.

**Почему id не равен индексу:** индекс — текущее положение в массиве, id — идентификатор записи, он сохраняется после удаления соседей. Поиск tasks[id] вернул бы неверный элемент.  
**Почему getTaskStats возвращает число, а не строку с процентом:** расчёт отделён от представления. Округление — задача вывода (progress.toFixed(1)), расчётная функция возвращает точное значение, пригодное для дальнейших вычислений.
**Какие объекты копируются при изменении задачи:** создаётся новый массив (map/filter/spread) и новый объект изменённой записи ({ ...task, ... }). Неизменённые объекты переиспользуются без модификации.
